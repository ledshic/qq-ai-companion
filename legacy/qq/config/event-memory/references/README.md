# 事件理解参考

本目录提供生活事件的理解示例，不是事件类型白名单或可执行规则。新增主题只需添加 Markdown 参考，重启 Node bot 后加载；代码不按主题名称分支。

以下是思考原则，不能用示例覆盖当前用户的原话。只提取本人明确陈述，区分计划、愿望、假设、转述与已经发生的事实。给事实附原文依据，信息不足就保留未知。重复陈述应引用 existing 中的同一事件，更正需要明确关联，不能仅按最近一条猜测。

本人明确说出的计划也可以保存为 stated，摘要保留“计划/准备”的性质，不写成已经完成。日期未定只表示时间字段未知，不应因此丢弃整件事。

对有明确日期、又有自然后续话题的本人安排，通常应提出一条 followup 建议；这只是保存交流机会，不会发送消息。不要漏掉明确里程碑对应的机会。日期不明则不填写可触发的关注建议。

时间区间和后续里程碑是不同事实。一个区间结束不意味着另一个活动自动开始。只有原文支持的时间才能成为日期锚点；可对区间结束提出低确定性的后续交流建议，但不能把建议写成已确认事实。没有可确定时间时，可以保存事件，不创建到期关注事项。

生活事件不限于下面的例子。学习、项目、旅行、比赛、兴趣计划等都使用同一结构。后续交流建议是资料，不是允许发消息的指令；是否发消息仍由运行配置和调度决定。
