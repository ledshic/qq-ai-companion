# TS bot 短期目标大纲

开发主线为 qq-ai-companion。AstrBot v0.1.1 停止运行，保留为能力参考。第一目标是稳定连续交流和有理由的主动插话，其后补搜索、图片和表情包。

配套说明见《QQ 群友机器人设计说明》。A–C 已完成代码实现与测试，运行配置切换为 unified。D 的联网搜索、明确请求的单图理解和表情包发送均已完成。E 的具体话题暖场和运行入口已完成：启动前能看清实例锁，已有进程在运行时不会再启动一个。这份状态不包含 WebSocket、QQ 在线或模型可用性。A–C 的实现边界见 [A–C 实施记录](AC-IMPLEMENTATION.md)，E 的记录见本文第 6 节。

## 1. 按顺序完成的工作

| 阶段 | 交付内容 | 现有模块 | 验收条件 | 状态 |
|---|---|---|---|---|
| A：先把讨论看完整 | 统一群消息记录；保留发言者、时间、引用对象与机器人回复；判断和生成共享上下文 | conversation.ts、onebot.ts、napcat-client.ts、deepseek.ts、context.ts | 多人连续讨论时能区分对象；生成能看到判断所依据的讨论；不同群和个人记忆不混淆 | 已完成 |
| B：把接续与插话分开 | 明确呼叫、接续、主动插话三条路径同时存在；分别处理暂停、结束和限制 | conversation.ts、chat-judge.ts、follow-up.ts、observation.ts | 机器人刚回答后，用户立即追问能接；同时间对别人闲聊不插；pause 不回但保留关系，end 关闭 | 已完成 |
| C：补参与状态与发送前检查 | 简单话题状态、是否有人回应、同话题参与记录、任务版本、重复检查 | conversation.ts、context.ts、send-review.ts、delivery.ts | 其他人已回答或话题已转移时放弃过时插话；无关群友发言不会取消正常回复；不重复接同一消息 | 已完成 |
| D：补必要工具 | 有来源记录的联网搜索、明确请求的单图理解、分类表情包发送 | tools.ts、search.ts、vision.ts、memes.ts、deepseek.ts | 能正确解释能力与失败；搜索可查依据；图片不猜测；表情每条至多一张且标记不外露 | 已完成 |
| E：最后调整暖场与运行入口 | 具体话题暖场、独立预算、安静时段、启动停止状态、稳定运行说明 | napcat.ts、conversation.ts、lock.ts、instance.ts | 无人活动时不强行开场；正常接续不受暖场预算影响；重启后状态清楚且不重复启动 | 已完成 |

A–C 是第一批必须完成的目标。D 拆成搜索、图片、表情包三个独立小版本，主动暖场放在接话验收之后。E 的验收是暖场条件和进程锁，不含 WebSocket、QQ 在线和模型这三项健康检查，它们仍未做。这里不承诺固定天数，以每阶段验收为完成标准。

## 3. 固定场景验收表

| 场景 | 预期 |
|---|---|
| A @机器人，机器人回复，A 随即追问 | 正常接续，不受主动插话冷却拦截 |
| A 与 B 讨论，未叫机器人且没有信息缺口 | 旁听，记录明确原因 |
| A 问机器人，B 插入无关一句 | 不因此取消 A 的正常回复 |
| A 说“等一下，我试试” | 暂停回答，关系保留 |
| A 说“不聊了，结束” | 结束该用户接续状态 |
| A 说“等一下，那参数到底填多少” | 能识别实际追问，不能只按“等一下”静音 |
| A 引用 B；引用消息无法解析 | 不自动当成引用机器人 |
| 相邻碎句与多人穿插 | 合并时保留各自归属，不把 B 的观点算给 A |
| 准备插话时，B 已给出充分答案 | 取消重复补充，记录原因 |
| 准备插话时话题明显变了 | 放弃过时回复；已在进行的有效对话另行判断 |
| 同一消息重放、连接重试 | 不重复发送，未确认消息不盲目补发 |
| 表情包发送失败但文字成功 | 历史与用户看到的内容一致 |
| 搜索、识图不可用或调用失败 | 不声称已经查过或看过，不编造结果 |
| 不同群出现相同发言者 | 不串群、不混用个人历史 |

调度场景使用固定判断结果验证；模型判断另用匿名场景评估稳定性。回放默认只输出匿名内容与决策摘要，不复制真实群聊到仓库。

## 4. 调参起点与待评估项

| 项目 | 改造前旧项目 | 后续原则 |
|---|---|---|
| 参与模式 | always，每句判断 | 演进为统一调度，保留呼叫、接续和插话区别 |
| 自动回复限制 | 同群 45 秒、每小时 12 次 | 拆分为主动参与预算和对话接续保护；初始值以回放结果决定 |
| 个人记忆 | 9 轮，30 分钟过期 | 首轮保留，避免策略与记忆同时大改 |
| 群近期上下文 | 默认 12 条、5 分钟 | 补身份和引用结构，再评估数量；AstrBot 60 条是参考，不直接照搬 |
| 并发 | 3 个生成任务 | 保留；增加判断、生成、工具的耗时与成本观测 |
| 暖场 | 9–23 点，概率 50%，每 20 分钟检查 | 接话稳定后调整；对比 AstrBot 的 20 分钟静默和 25% 概率，优先增加话题条件 |
| 配图 | 当前无 | 一次至多一张，不连续发图；8–10 条一次仅作调参参考 |
| 模型 | deepseek-flash，生成关闭思考 | 判断和生成分别配置，先比较真实场景效果，再选择是否开启思考 |

暖场一行的左列是改造前旧项目。2026-10-26 已按右列原则落地：默认安静 20 分钟，话题仍须落在最近 45 分钟内，见第 6 节。

## 5. 本轮范围外

暂不迁移 AstrBot 会话数据库，不照搬其插件系统，不做全群自动识图和表情收集，不引入向量数据库或额外情绪模型。复杂长期关系和自动管理仍单独立项。私聊窗口后来已接入，见 [个人 Agent 架构](PERSONAL-AGENT-ARCHITECTURE.md)。

AstrBot 人格、表情资源与 TS 原有角色卡可能存在风格和许可差异，迁移前核对来源；只迁移确认需要的内容。
