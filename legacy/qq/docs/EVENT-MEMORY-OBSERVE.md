# 事件记忆观察阶段实施记录

日期：2026-10-26。阶段：保存、聊天召回与主动决策观察，不主动发送。阅读顺序见 [文档索引](README.md)。

架构修订：主题专用规则已改为[参考文本驱动的通用事件模型](EVENT-REFERENCE-MODEL.md)。以下以通用事件模块为当前实现，休假仅作验证示例。

## 本阶段行为

接收有真实消息来源的发言，批量提取本人事件，保存证据、事件与关注事项。到期检查只记录 not_due、no_presence、ready_for_review 等观察结果。ready_for_review 表示可以进入社交与预算检查，不代表允许发送。已接入[主动决策观察](EVENT-INITIATIVE-OBSERVE.md)，仅保存判断和通过审查的候选台词。

事件运行时没有发送或 QQ 工具接口；通过注入接口委托应用层生成观察草稿；配置仅接受 off/observe，on_presence 会在启动配置校验时被拒绝。现有普通聊天、接续和原有主动参与功能保持原有策略；事件功能不新增任何主动消息。

| 模块 | 责任 |
|---|---|
| `src/memory/events/runtime.ts` | 通用采集、批次执行、取消、观察；通过注入接口运行领域模块 |
| `src/memory/events/store.ts` | SQLite 新表、事务、去重、来源、版本、保留期、关注事项与清空 |
| `src/memory/events/extractor.ts` | 统一模型请求与匿名资料；不解释休假日期 |
| `src/memory/events/observe-policy.ts` | 通用时间窗口、出现条件、版本检查；不生成台词 |
| `src/memory/events/domains/event.ts` | 通用事件、区间、时间点、里程碑及有依据的后续建议；不按主题分支 |
| `config/event-memory/references/` | 保存生活事件的理解参考与例子；新增主题不要求修改代码 |
| `src/memory/events/time.ts` | 日期与自然日规则，由业务模块调用，不由引擎推断 |
| `src/memory/events/domains/contact.ts` | 明确的称呼、调侃与主动联系偏好 |
| `src/memory/events/application.ts`、`controls.ts` | 注册领域模块、解释用户命令、应用偏好限制 |

新增生活主题只需补充参考文本；EventDomain 仅保留为不同数据协议的扩展接口，不给每个主题注册模块。测试验证了任意新主题共用同一解析与关注投影逻辑。

## 配置与运行

```dotenv
EVENT_MEMORY_ENABLED=true
EVENT_MEMORY_GROUPS=<允许采集的群号，多个用逗号分隔>
EVENT_MEMORY_SCOPE=addressed
EVENT_FOLLOWUP_MODE=observe
```

示例配置默认关闭。addressed 只采集 @、句首称呼或已验证引用机器人消息的本人文本；group 才会采集普通发言，需要另外明确启用。允许群为空时不能启用，不会自动覆盖全部群。

已按用户选择准备为一个指定群启用 addressed/observe。日志仅显示群数量，不写群号或发言原文。实际启停结果以本节后续运行记录为准。

执行命令：`pnpm typecheck`、`pnpm test`、`pnpm replay:events`。回放无需密钥，不连接 QQ，不调用真实模型，覆盖从周五建项、重启、到周一本人出现的过程。

## 来源、存储与恢复

- 事件来源不依赖机器人回复成功；验证引用后也可补采集。按群与消息 ID 持久去重；普通发言的出现记录仅保留去重元数据，不保存其正文。
- 同群同人聚合 3 秒，连续消息最多等待 10 秒；一批最多 10 条、4000 字。每群每小时最多 12 次提取请求，预算保存在数据库，重启不清零。
- 模型请求最多 5 秒，失败不自动重试。尚未开始的来源可以在重启后继续处理；已开始但被中断的批次标记 interrupted，不重复调用。
- 输入有效期 24 小时，未来超过 5 分钟的时间戳不参与采集。原文收件保留 24 小时，事件/必要证据最多 30 天，模糊更正提议 7 天；无正文去重标记保留 30 天。
- 明确偏好可持续保存到本人更改或清空。关闭主动联系使待观察事项取消；重新开启不自动恢复旧事项。命令与自然语言偏好按更新时间决定哪个优先。
- 新表不改变原 sessions 表。SQLite 初始化失败时停用事件功能并输出状态，正常聊天继续可用；容量或候选校验失败只拒绝该批次。

提取结果只引用 source-N/event-N 别名，现有事件的证据主键不会发给模型。日期基于来源消息时间，首版业务仅支持 Asia/Shanghai 自然日；相对日期、明确年月日和可消歧的星期可解析。缺少时间、工作日、半天及歧义星期保留未知。

## 更正与控制

| 输入 | 本阶段处理 |
|---|---|
| 明确假期及返岗日期 | 保存独立事实和假期后续关注事项 |
| 只知道假期结束 | 后续事项只能提结束或询问近况，不确立复工事实 |
| 只说放两天假 | 保存未知日期事件，不创建某天复工事项 |
| 愿望、假设、明显第三方或引文 | 保守拒绝作为本人休假事实 |
| 更正/撤回且能唯一关联 | 事件版本变化，取消旧事项；新日期不明则不补猜 |
| 无法唯一关联的更正 | 保存短期提议，不任意撤销多个事件 |
| `/清空长期记忆` | 删除本群本人事件、证据、偏好与事项，递增 epoch（清空版本），保留无正文去重标记 |
| `/清空记忆` | 同时清除原个人历史和长期事件；清除短期快照中相关本人记录，阻止旧资料立即恢复 |
| `/主动关心 关`、`/主动关心 开` | 保存确定性偏好；当前阶段仍不主动发送 |

清空、关闭、断开和明确呼叫优先于后台提取。晚到结果必须通过 scope epoch 和批次状态检查，不能复活已清空内容。事件修正还校验目标版本，避免覆盖更新后的事实。

## 程序与模型验证

新增测试覆盖日期强度、未知时间、假设和转述、重复陈述、清空、恢复、小时预算、证据隔离、引擎扩展、发送失败仍记忆、命令应答与断开取消。背景任务共用现有并发限制，最多一个；并发容量大于 1 时为前台保留至少一个名额，明确呼叫可取消背景任务。

六组匿名合成样本实际调用当前 DeepSeek 模型：明确日期正确形成关注事项，未知日期不补猜，愿望和第三方发言不新增事实，更正取消旧事项并建立新日期事项，明确拒绝主动联系和调侃可保存偏好。试验只在独立内存数据库中运行，没有写入真实用户记忆或发送 QQ 消息。

这不是设计中进入主动发送试运行前的 90 样本验收。社会时机和草稿事实检查现已进入观察验证；主动发送预算、结构化发送及发送结果不明恢复仍属于后续阶段。后续已接入[长期事件聊天召回](EVENT-MEMORY-RECALL.md)，普通聊天追问可以使用有效事件资料；主动发送的验收仍属于后续阶段。

容量起点为每群 200 条有效事件、每人 20 条、每群 100 条待处理来源。超出容量会拒绝该批次并记录原因。受支持语法外的事实可能无法提取；被前台任务取消的已开始提取不自动重试，可能漏记，可由后续本人再次陈述补充。

主题结构修订后，全量 208 项测试、类型检查与离线回放通过。Node bot 已加载通用事件协议和参考目录，事件库版本为 2，检查无旧类型记录残留；采集仍为单个允许群、addressed、observe，QQ 在线且连接正常。当前日期模型处理与主题理解是不同层次，原文证据和未知时间约束继续保留。

真实模型再次使用休假、考试、个人制作计划、愿望、转述、日期未定六组样本。三个不同主题能共用协议形成事件与关注建议；愿望和转述不入事实库。曾出现漏提取、索引数字被写成字符串及请求不可用，已加强参考说明、对安全等价的数字表示归一化，并拒绝缺少约定数组的响应。个别请求仍未获得可用结果，按原有失败策略不写入、不重试，不能声称已达到稳定提取率。
