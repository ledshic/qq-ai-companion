# TS bot A–C 实施与验证记录

2026-10-23 已实现统一群上下文、独立的连续接话与主动插话，以及真正发送前的时机复查。运行模式为 unified；AstrBot 两个容器保持停止，TS bot 使用旧项目现有 NapCat。搜索、图片理解和表情包等 D–E 目标未纳入本次实现。

## 实现结果

| 阶段 | 实现内容 | 主要文件 |
|---|---|---|
| A：统一上下文 | 群消息保留发言者、昵称、时间、消息标识、提及与引用；可确认的同群引用补齐原文；机器人消息在送达回执后记录，保留回应对象与触发消息 | context.ts、message.ts、onebot.ts、napcat-client.ts |
| A：判断与生成一致 | 使用同一份不可变讨论快照；个人历史继续按群和用户隔离，不将他人的话存进当前用户历史 | conversation.ts、deepseek.ts、group-judge.ts、follow-up.ts |
| B：分开参与规则 | 明确呼叫优先；连续接话按 continue／pause／end／uncertain 分流；有效接续成功后续期，不占主动插话预算 | conversation.ts、observation.ts、napcat.ts |
| B：限制主动参与 | 主动插话单独使用原有冷却和小时上限；同群只保留一个进行中的主动参与任务；原有 window／always 可用于回退 | conversation.ts、napcat.ts |
| C：参与状态 | 记录话题、参与依据、是否有人回应；同话题未获回应时避免再次主动参与；断线保留去重与主动参与预算 | context.ts、conversation.ts |
| C：发送时机 | 生成期间、发送排队期间及每段写出前，讨论变化都会触发语义复查；复查期间再次变化则放弃当次发送 | conversation.ts、delivery.ts、napcat-client.ts |
| C：取消与部分送达 | 同一用户补充、暂停或新请求可使旧草稿失效；无关群友发言不直接取消正常对话；复查异常仍保留已确认送达的前缀 | conversation.ts、delivery.ts |

角色卡仍保留原有短句、幽默和身份设置，调整了重复决定“是否开口”的主要规则。更换角色卡文件后需要重载 TS 进程，本次未提供多卡热切换。

## 当前配置与边界

| 配置 | 当前行为 |
|---|---|
| FOLLOW_UP_MODE | unified |
| GROUP_CONTEXT_MESSAGES | 默认 60 条，按群独立保留 |
| GROUP_CONTEXT_SECONDS | 默认 300 秒，在读取快照时也清除过期消息 |
| 上下文文字上限 | 约 16000 字符，引用文字计入限制；这不是精确 token 上限 |
| WINDOW_SECONDS | 当前 90 秒，成功接续后续期；pause 保留关系，end 关闭 |
| AUTO_REPLY_COOLDOWN_SECONDS | 当前 45 秒，只限制主动插话 |
| AUTO_REPLY_HOURLY_CAP | 当前 12 次，只限制主动插话 |
| MEMORY_TURNS | 当前 9 轮，个人记忆原有 30 分钟过期规则不变 |
| MAX_INFLIGHT | 当前最多 3 个任务，继续使用原有任务等待与取消机制 |

只有实际确认送达才更新成功回复历史和参与次数；部分送达仅记录已确认的部分。没有确认属于机器人的普通引用不自动唤醒；引用查询失败时，明确 @ 或昵称呼叫仍然有效。

去重保存在内存中，覆盖近期重复事件和断线重连，不能保证进程重启后永久去重。群上下文与话题状态也不持久化；本次未迁移 AstrBot 历史数据。

## 数据发送范围

内部仍用实际标识关联消息；发给模型时，将群、账号及消息标识字段转换为快照内一致的别名。判断结果中的别名经校验后映回内部标识，未知对象或不存在的依据不能触发回复。旧插话及暖场重复拼接的资料也使用同一别名规则。

昵称和消息正文仍作为讨论资料发送，不做全文个人信息脱敏。群讨论只保存在内存，个人会话继续使用原有 SQLite；默认日志不输出完整快照。本次固定回放及接口验证全部使用匿名合成资料。

## 测试与评审

- 类型检查通过，91 项自动测试全部通过；原有 54 项行为测试保持通过。
- 新测试覆盖上下文快照一致性、不同群和发言者隔离、引用资料、真实 WebSocket 回执、续期、预算隔离、暂停与结束、碎句、重复事件及断线。
- 竞争场景覆盖生成期间已有答案、话题变化、引用慢查询、排队后讨论变化、异步复查失败和分段发送期间有人回应。
- 独立代码复核发现的回执对象遗漏、引用资料缺失、参与状态覆盖和慢引用竞争均已修复并增加测试。
- 实际模型接口发现模型字段传递和否定决策元数据容错问题，已修复并补请求断言。8 个不同匿名场景最终均通过；最终角色卡的发言者归属也做过复验。

实际模型场景包含：旁听他人交流、开放求助、问题已解决、话题已转移、暂时暂停、含“等一下”的真实追问、无关群友穿插，以及分清不同人的偏好。小样本结果只说明这些场景通过，不代表整体群聊准确率或长期自然度已得到统计验证。

```bash
pnpm typecheck

```

pnpm replay 使用固定判断结果回放匿名场景，不连接 QQ 或模型；它验证调度流程，不评价模型语义质量。

## 运行验证与回退

仅重载 TS 进程，未重启 NapCat。真实接口确认 QQ 在线且核心就绪，TS WebSocket 保持连接；AstrBot 两个容器保持停止。未向群里主动发送测试消息，真实群聊体验仍需后续观察。

运行日志为旧项目 data/runtime/tsbot-ac.log，PID 为 data/runtime/tsbot.pid。需要回退参与策略时，在 .env 将 FOLLOW_UP_MODE 改为 always 或 window，再正常停止并启动 TS 进程；不要重复启动另一个实例，也不要同时启动 AstrBot 的 NapCat。

系统级开机自启和异常守护仍属于 E 阶段，当前进程为独立后台运行。
