# 小鲸鱼模块化人格变更设计

状态：待实施。日期：2026-10-26。读者：本仓库开发与维护者。

实施进度：无状态首版已完成代码与程序测试，见[首版实施记录](PERSONALITY-IMPLEMENTATION.md)。以下保留原设计内容；真实模型效果评估和后续状态能力仍待完成。

后续评估见[人格运行时与决策引擎升级评估](PERSONALITY-RUNTIME-EVOLUTION.md)。实施时优先采用该文对观察与计划分离、分析复用、只读计划传递以及状态提交分类的修订；本文保留初版方案，便于比较取舍。

## 设计结论

首版增加“表达决策”：根据本次请求及其上下文，选择认真解释、普通闲聊、继续接梗或支持回应，生成阶段读取对应的表达模块。小鲸鱼的身份、基本性格和事实边界始终存在。模块可以组合，例如“认真解释 + 保留直率语气”，不切换成另一个角色。

首版不增加情绪分数、长期关系数据库或多 Agent 框架。先验证显式表达决策能否改善现有角色卡的执行稳定性，再决定是否增加跨轮状态。本文描述拟议变更，不代表已经实现或验证效果。

## 当前实现与具体缺口

| 代码与记录 | 已有行为 | 本次设计的依据 |
|---|---|---|
| `config/personas/dafeiyu.md` | 已区分认真提问、低落、闲聊、反串；强调继续同一个梗 | 规则基本齐全，缺少可检查的单轮选择结果；不能把现有能力算作新增功能 |
| `src/persona.ts` | 启动时读取完整角色卡，追加工具与运行说明 | 可以拆分固定内容与场景模块；能力说明继续由程序生成 |
| `src/deepseek.ts` | 工厂创建时固定 system 提示；每轮追加匿名群上下文、个人历史及本次请求 | 动态模块必须移到每轮构建，不能只在工厂创建时选择；工具循环中保持同一决策 |
| `src/vision.ts` | 单独调用角色提示，接收群上下文和当前图片；没有文字生成器的个人历史入参 | 必须单独接入，不能只修改文字路径；不得假定识图拥有同等个人历史 |
| `src/context.ts` | 提供不可变讨论快照、目标用户、触发消息和参与依据；模型侧替换标识符 | 表达判断复用当前快照与匿名化，不新建一套全群上下文 |
| `src/conversation.ts` | 管理呼叫、接续、插话、暖场、取消和发送前检查；成功送达后写个人历史 | 人格不能决定是否发送、扩大工具权限或绕过取消 |
| `src/memory.ts`、`src/store.ts` | 按群和用户保存已发送对话，默认 9 轮、30 分钟失效 | 这是短期会话历史，不是长期关系；首版无需数据库迁移 |
| `src/memes.ts` | 根据拟回复和群上下文选图、复核语义，并维护送达相关频率 | 保留现有复核；表达决策可补充“本轮不适合调侃”的约束 |
| `docs/SOCIAL-BEHAVIOR.md` | 已记录避免固定权重，后续评估社交意图状态 | 本版沿用该方向，重点验证收益，而非继续堆角色规则 |

## 首版运行流程

```mermaid
flowchart LR
  A[现有参与判断] --> B[冻结当前讨论与目标]
  B --> C[形成表达决策]
  C --> D[组合固定人格与表达模块]
  D --> E[生成文字或识图回答]
  E --> F[现有时机与配图检查]
  F --> G[发送确认后记录实际内容]
```

表达决策在任务已获得现有生成并发名额后执行，沿用任务取消信号。判断器不接收原图、图片下载地址或真实账号标识，不新增对普通旁听消息的模型请求。

## 模块与数据契约

固定部分分成身份、基础表达、事实边界三份；动态部分分成认真解释、闲聊、接梗、支持回应四份。模块来自受版本管理的本地文件，只允许程序按枚举选择；用户消息和模型返回的自由文本均不能直接追加为 system 指令。

```ts
type ExpressionMode = 'neutral' | 'explain' | 'casual' | 'play' | 'support';

interface ExpressionDecision {
  mode: ExpressionMode;
  banter: 'off' | 'light' | 'normal';
  basisIds: readonly string[];
  source: 'classifier' | 'fallback' | 'local';
}
```

`neutral` 复用当前角色卡的场景自适应规则，作为信息不足或判断失败时的选择。表达决策只描述本轮行为，不写“用户患有某病”“关系亲密”等个人标签，不包含需要向用户隐藏的推理过程。

| 决策 | 主要行为 | 约束 |
|---|---|---|
| explain | 先回答具体问题，必要时解释 | 可以直率，不强行吐槽；认真核实能力时说清实际结果 |
| casual | 跟随当前话题自然交流 | 不强行搞笑，不每轮追问 |
| play | 继续双方已经建立的玩笑 | 不重开旧梗；明确要求认真或出现现实行动意图时退出 |
| support | 回应明确表达的困扰，提供合适帮助 | `banter=off`，不嘲讽、不诊断、不自动写入长期情绪标签 |
| neutral | 由原有规则结合上下文表达 | 不增加熟悉度假设，不主动激活强烈调侃 |

组合顺序为固定身份与边界、运行能力、基础表达、当轮模块。事实与能力约束、用户要求认真等限制优先；场景模块不能覆盖身份、对象、工具权限和送达事实。长度继续随问题决定，不把每个模式做成固定字数或固定答句。

## 表达判断的接入选择

首版采用可注入的独立轻量判断函数，输出上述有限 JSON（结构化数据）。不把表达判断塞进参与判断：明确呼叫并不总会调用参与判断，发送前复查的职责也不同。暂不改变文字生成的纯文本返回协议，避免影响工具调用与分段发送。

这是有成本的选择：正常启用时，每个生成任务最多增加一次模型请求。建议首轮超时上限为 3 秒，不重试，失败继续使用 `neutral`；这是一项待测配置，不能视为现有能力或时延承诺。分别记录判断耗时、失败率与调用次数，再决定是否值得默认开启。

具体输入、验证与失败行为如下：

- 输入使用本次请求、已有个人历史和 `modelContext` 转换后的快照。对话资料作为数据提供，不将其声明改成规则。无上下文的旧入口可用当前请求和已有历史，但不得返回虚构的依据消息。
- 优先根据触发消息、目标发言者、明确引用与参与依据定位本次交流。其他群友的情绪或玩笑不自动覆盖当前请求；不能按关键词给整个群指定统一场景。
- 当前请求不在快照时，以独立的 `current-request` 数据提供；模型只能引用实际提供的消息别名或该保留标记。解析端验证枚举、字段类型、数量和依据集合，拒绝任意指令文本。
- 空 @ 应声走本地简短回应策略；暖场使用轻度闲聊策略，不推断被安慰对象。两条路径均不增加判断请求。无模型模式继续走现有固定回答。
- 首版每轮重新判断，无跨轮情绪状态；历史中的语气仅作为证据。用户说“认真点”“不要开玩笑”时，当前意图优先于之前的 play。不能仅凭历史判断持续演下去。
- 判断器只接收图片任务的文字和讨论资料。无法读图判断情绪时选择 neutral；识图生成器仍依据实际图片调整表达，不能被 play 决策强制要求开玩笑。
- 超时、网络错误或格式错误使用 neutral；父任务取消必须继续抛出取消，不得被捕获后生成备用回复。工具轮次与重复短句改写复用同一表达决策，不重复分类。

建议先以 `PERSONALITY_MODE=legacy|modular` 控制上线，默认 legacy。modular 才启用判断请求；legacy 保留完整原卡。拆分后的固定模块与动态模块需核对原规则，避免在整理文件时丢失玩笑与能力核实的区别。

| `src/persona.ts` | 保留 legacy 构建函数，增加按配置和表达决策组装提示的函数；模块加载与格式检查在启动时完成 |
| `src/deepseek.ts` | 每次回复前判断一次并组装提示；保留工具和重复改写逻辑、纯文本返回形式 |
| `src/vision.ts` | 在图片校验成功后形成表达决策；复用同一组装器，继续追加图片专有真实性约束 |
| `src/napcat.ts`、`.env.example` | 校验模式配置，向文字与图片工厂注入同一人格服务配置；启停输出实际模式 |
| `src/memes.ts` 及媒体上下文传递 | modular 下共享本轮表达限制；support 或 banter=off 时跳过自动配图，明确请求图片仍按真实意图和原复核处理 |
| `src/conversation.ts`、`src/context.ts` | 在调用生成器前提供每任务的表达元数据容器，生成器写入后供配图读取；不得跨任务共用可变状态。ReplyContext 快照仍保持不可变 |
| 相关测试与匿名评估样本（新增） | 覆盖协议、请求构建、取消及场景行为；不把真实群聊提交进仓库 |
| `README.md` | 补模式、额外请求成本与回退说明；另行修正“搜索图片尚未实现”等已过期描述 |

表达元数据建议通过额外的任务局部入参传递，不把 `generate` 的返回值从字符串改成对象，避免同时重写全部发送调用。文字与识图适配器均需接受该可选入参，完成后把只读决策交给配图阶段。旧调用方未提供时保持原行为，禁止使用“最近一次决策”全局变量。

## 后续的关系与连续性

首版评估通过后，再拆为独立变更。当前需求不要求立刻落数据库，避免同时改变人格、历史和调度。

| 后续能力 | 建议最小规则 |
|---|---|
| 表达连续性 | 保存“当前接梗模式及依据”，按群、用户和可验证话题隔离；建议有效期从 5 分钟起试验，明显认真请求立即覆盖 |
| 情绪惯性 | 仅模拟机器人的短期表达状态；使用实际经过时间衰减，读取时计算，禁止按消息数量衰减；不把一个用户的冲突带给另一个用户 |
| 关系记忆 | 先保存用户明确给出的称呼、互动偏好及可引用的共同经历；保留来源、更新时间、过期和撤销方式，不从聊天次数推导信任或调侃许可 |
| 写入条件 | 当轮临时决策可在生成前存在；跨轮状态仅在有效发送确认后提交一次。取消、失败、未确认发送不得提交，部分成功只依据实际送达内容 |
| 清空与并发 | 扩展 `/清空记忆` 时明确同时清除本群该用户的关系与表达状态；用版本号拒绝清空前任务的延迟提交。另行决定是否删除群公共上下文，不宣称已经全部遗忘 |
| 存储 | 独立接口与表，按群和用户隔离，限制容量及保留时间；不把 snapshot 内的 person-N 别名当持久主键，不在模型请求中恢复真实账号标识 |

现有个人历史只记录已确认发送内容，但群上下文仍会短暂保留讨论。后续加入“忘记”功能时必须区分这两类数据，并更新用户可见说明。

## 验证与实施顺序

先完成模块拆分和 legacy 回退，再接入表达判断及文字、识图、配图路径，最后用相同匿名样本对比两种模式。行为评估用真实模型另行运行，不连 QQ 发测试消息；离线测试只验证确定的程序行为。

| 验证层 | 必须验证的结果 |
|---|---|
| 纯函数与请求协议 | 无效枚举和伪造依据被拒绝；用户文本不能成为 system 模块；判断失败仍可回复；工具调用与短句改写不重复分类 |
| 取消和并发 | 判断期间新呼叫、断开连接能终止旧任务；A、B 并发不串表达决策；配图读取所属任务的限制 |
| 全路径 | 呼叫、接续、主动插话、暖场、空 @、直接单图与关联单图；旧模式以及无模型入口行为保持可用 |
| 原功能 | 发送前时机复查、部分送达、个人历史、匿名化、搜索与识图真实性测试继续通过 |

行为样本至少覆盖以下转变，每组建议重复 5 次；该数量用于发现明显问题，不作为统计显著性证明。

| 匿名情境 | 验收重点 |
|---|---|
| 连续接同一个荒诞梗 | 保留角色，继续当前设定，不重开梗或无故核验工具 |
| 玩笑后明确说“认真说，实际能做吗” | 当轮停止表演，准确说明能力 |
| A 认真提问，B 同时玩梗 | 回应 A，不被 B 的语气带走 |
| 用户表达困扰 | 不嘲讽，不发不合适的配图，不诊断用户 |
| 技术求助中带一句自嘲 | 优先解决问题，避免整轮误判为玩笑 |
| 同一用户在不同群聊天 | 无关系和人格状态串用 |
| 玩笑语境里要求识别严肃截图 | 图片分析准确，不强行输出俏皮话 |
| 空 @ 与暖场 | 不延续旧任务，不捏造关系或状态 |

记录每条样本的对象正确性、认真与玩笑转换、身份一致性、事实可靠性、重复措辞以及额外请求耗时。两种模式各使用相同样本，保存模型与配置版本；不能用“分类 JSON 正确”代替“最终回复自然”。

实施检查运行 `pnpm typecheck`、`pnpm test` 与 `pnpm replay`。默认开启 modular 的条件是：原功能检查通过，行为对比无新增事实或对象错误，且表达改善足以接受额外请求成本。未达条件时维持 legacy，不自动推进关系和情绪状态。
