# CLI 任务列表与恢复记录

2026-10-29，面向使用者和仓库维护者。交互式 CLI 已能发现本人已有任务，按编号恢复观察或查看最终状态。列表和恢复复用正式服务与 SDK（共享服务客户端），不创建新凭据、不重新提交消息，也不自动重新执行失败任务。

## 使用方式

服务需包含本次新增的列表接口，使用已有凭据进入 `pnpm agent:cli chat`。即使没有选择会话，也可查询任务；无需记住上一次退出时的任务标识。

| 命令 | 行为 |
| --- | --- |
| `/tasks`、`/tasks active` | 查看本人的排队中、运行中任务，每页 20 项 |
| `/tasks all` | 查看全部状态，包括完成、失败、取消和服务重启后的中断 |
| `/tasks more` | 按原筛选读取下一页；页末明确提示，没有自动读取所有历史 |
| `/resume` | 显示未完成任务，等待选择，不自动接管 |
| `/resume #1` | 重新查询编号对应的任务，再观察当前输出或查看终态 |
| `/resume <runId>` | 保留原有完整标识入口，不依赖列表缓存 |
| `/cancel`、Ctrl+X | 取消当前正在观察的任务；浏览列表不取消或切换任务 |

编号随翻页继续增长，最近显示的 200 项可按编号选择；更早的编号失效，不会被重新分配给其他任务。仍可继续翻页或使用完整标识。重新执行 `/tasks`、`/tasks all` 或不带参数的 `/resume` 会从新列表重新编号；查询失败也会清除旧编号。

列表显示状态、任务标识、会话标题与标识、更新时间和错误代码，当前观察项有标记。标题中的换行和终端控制序列经过过滤，不能伪造新的列表行。正文、回答、推理和流式草稿不出现在列表中。

## 恢复与取消规则

恢复先按当前凭据读取任务，再核对任务和会话，最后沿用原有输出订阅。列表中的状态可能已变化：完成后只显示保存的结果，失败、取消、中断只显示实际状态；排队或运行中才继续观察。恢复不会调用模型重跑，也不改变运行时暂停状态。

每次仍只观察一个任务。另一个任务尚未结束或提交结果未确认时，不允许通过编号替换当前任务。观察连接中断后可重新选择同一任务；`/retry` 仍用于确认原来的提交，不用于重跑失败任务。

恢复中的输出继续检查认证、来源有效性和取消状态。来源在选择后、订阅前撤销时，首个草稿也不能发送；观察期间撤销则清除草稿并阻止写入最终回答。退出只结束本地观察，任务保留在服务端，下次可从列表重新选择。

## 正式 API 与客户端

新增只读接口 `GET /api/v1/runs`，沿用原有认证和浏览器来源检查。管理设备与普通已授权设备都只能看到当前拥有者的任务，客户端不能传入其他拥有者身份。

| 查询参数 | 行为 |
| --- | --- |
| `status` | `all` 或 `active`；API 默认 all，交互式 CLI 明确请求 active |
| `limit` | 1–200，默认 50；CLI 请求 20 |
| `before` | 上一页的 nextCursor，值为上一页末项的任务标识；其他拥有者或不存在的游标返回 404 |

按创建顺序从新到旧返回摘要，新加入的任务不会插入已翻过的后续页。状态在每次查询时读取，不保证多页共同构成同一时刻的快照；需要最新未完成任务时重新 `/tasks`。

```ts
interface RunPage {
  runs: RunSummary[];
  nextCursor: string | null; // null 表示没有下一页
}
// RunSummary: id、conversationId、conversationTitle、state、error、createdAt、updatedAt
```

SDK 使用 `client.runs({ status, before, limit })`；检查状态、日期、任务标识、重复项、摘要字段和游标一致性，拒绝夹带正文的响应。任务恢复仍使用 `client.run(id)` 与 `client.watchRun(id)`；既有 `client.resume()` 继续只用于恢复接收请求。

后续已增加 conversationId 筛选、交互式 `--here` 和单次 tasks 命令，SDK 用法、会话游标约束与最新验证见[会话筛选记录](AGENT-CLI-TASK-FILTERS.md)。本页保留任务列表首次交付记录。

实现直接查询原有任务与会话表，没有数据库迁移或新的持久任务副本。旧生命周期事件不作为列表来源，因此事件保留期不会影响发现任务。
