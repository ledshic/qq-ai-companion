# 长期事件聊天召回

日期：2026-10-26。状态：已实现；关注事项继续 observe（只观察，不主动发送）。

## 使用范围

在已启用事件记忆的允许群中，机器人收到明确呼叫或接续追问时，可以读取当前群、当前用户已经保存的事件。文字问题和图片附带的文字问题共用这条路径。单独 @、控制命令、普通群聊及机器人主动参与不触发召回。

采集仍限定为 addressed（明确叫到机器人），本次没有扩大范围。召回不会补录未保存的历史群聊，也不会等待尚未完成的后台提取。原有短期对话历史继续使用。

## 查询与回答

| 环节 | 当前实现 |
|---|---|
| 查询资料 | 按群和用户隔离，只读取未过期的有效事件；来源证据必须完整、有效且属于同一范围 |
| 候选范围 | 按更新时间排序，最多读取 20 条；给选择模型的是压缩摘要、日期和来源片段 |
| 相关性选择 | 有候选时调用一次模型，最多选 3 条；超时 3 秒，不自动重试；无候选不调用 |
| 回答资料 | 将所选事实、原始来源时间、记录时间和证据片段加入本轮用户资料，使用临时别名 |
| 状态区分 | matched 有相关资料；empty 本次未找到；unavailable 查询失败；disabled 未启用 |
| 发送前检查 | 再检查清空版本、事件版本和证据有效性；失效则停止发送旧答案 |

“本次未找到”不能解释成“你从来没说过”。计划不代表已经完成，未知日期不能补猜；当前明确更正优先于旧记录。来源时间用于理解当时的相对日期，更新时间不替代来源时间。图片追问可以引用文字记忆，但不能把文字记录说成看过的历史图片。

清空、撤回、更正、保留期到期都会影响可用资料。无法保全来源证据的事件不进入召回；多个来源中任一必要证据失效时也保守跳过。生成期间发生更新可能使本轮答案取消，当前不自动重试。

## 模块责任

| 文件 | 责任 |
|---|---|
| `src/events/recall.ts` | 查询隔离、证据检查、候选选择、错误状态与发送有效性检查 |
| `src/events/domains/event-recall.ts` | 将通用事件转换为聊天事实资料，不提供关注建议、偏好或待确认提议 |
| `src/events/application.ts` | 注册召回接口，运行时不包含具体主题规则 |
| `src/conversation.ts` | 在聊天生成前取得一次资料，工具调用期间复用，发送前检查有效性 |
| `src/deepseek.ts`、`src/vision.ts` | 将资料交给回答模型，约束来源、未知信息及指令边界 |
| `config/event-memory/recall.md` | 保存资料使用规则；具体主题示例仍在 `references/` 中 |

资料中的文字不作为系统指令执行。召回沿用版本 2 的事件库，无需数据库迁移或新增环境变量；初始化失败时正常聊天仍可继续。启动日志增加 `recall=enabled`，查询日志只记录状态、数量和耗时。
