# TS bot 表情包实施记录

2026-10-23：D 阶段的表情包发送已完成。复用暂停项目的贴吧图库，先为具体图片生成语义资料，再由 LLM（语言模型）根据讨论和拟回复选择一张或不配图；程序控制频率、重复和发送时机。

## 图库与语义

图库来自原 AstrBot 的 tieba-emoticons v1.1.0，共一百一十三张 PNG。图片、原始资源说明和独立清单已复制到本项目，运行时不依赖暂停项目的路径，也不访问插件云端服务。

使用现有 DeepSeek Flash 多模态接口逐张读取实际图片，保存核心含义、图中文字、发送者立场、回应对象、适用与不适用场景，以及模型自评置信度。全部一百一十三张均完成，最终失败项为零。标注包含版本号和文件哈希（用于检查图片是否变化），重复运行会跳过未变化且已完成的图片。

十八张含义不明确、自评低于 0.8 的图片暂不自动发送；其余九十五张是可选候选，不表示已经逐张人工确认。抽查发现原“难过”目录里的图实际是在憋笑，运行时按逐图含义判断，不依赖原分类随机取图。模型自评并非准确率，标注仍可能误解，支持后续人工修改并复核。

标注入口是 `pnpm memes:index`。图库语义供模型作为数据阅读，不作为指令执行。运行时校验语义版本、路径、文件大小与哈希，不能通过模型输出指定任意文件或网络图片。

## 选图与频率

先生成文字，再由辅助选图模型读取拟回复、统一群上下文及具体图片的语义清单，输出一个白名单图片编号或 null。没有合适图片时保持文字，不要求每次发图，不改写人格或正文，也不随机替换类别。

真实试聊发现“发抱抱安慰我”曾误选“自己委屈求关注”的图。因此对具体候选再做一次短语义复核，检查立场、对象和禁用场景；不通过或调用失败就取消配图，不继续随机挑另一张。

- 每个回复最多一张图片，文字在前，图片在后。首版不支持只发图的独立回复。
- 每群图片尝试后，至少经过七条已成功送达的其他回复，才再次允许选图；一条回复分成多个文本段也只计一次。
- 最近二十次表情尝试中的编号不重复。发送失败或超时也暂不重复尝试，避免未确认图片被反复发送。
- 各群独立，频率和编号记录写入本地私有状态文件，重载后保留。首次没有状态的群允许一次合适的配图，之后受间隔控制。
- 不为凑频率发图；用户拒绝图片、限定纯文字或没有贴切候选时不配图。暖场暂不配图。

`MEMES_ENABLED=true` 开启，`MEME_REPLY_GAP=7` 控制间隔，示例配置默认关闭。图库或状态损坏时停用配图、保留文字。选图请求限八秒，复核限五秒；低于频率条件时不会发起额外选图调用。

## 发送与历史

选图在本群发送队列中执行，避免并发回复绕过频率限制。选图结束后，以及图片真正写入连接前，均再次检查取消状态、连接和原有参与限制。讨论变化时，发送前语义检查包含拟配图片的含义，不只检查文字。

只有文本全部送达才继续发送图片，部分文本送达时保留确认过的前缀、不发送图片。图片以 OneBot 图片消息的 base64 数据发送，避免宿主机与容器路径不一致。发送前再次核对图片哈希。

收到图片 ACK（NapCat 成功回执）后，才向群上下文和个人历史加入实际表情编号、含义和已知配字；内部记录不作为文字发进 QQ，模型意外复述的内部编号和标记也会过滤。图片失败时历史只保留文字，超时不自动重发。

## 验证结果

图库全量语义已完成；一百六十九项自动测试全部通过，类型检查与差异空白检查通过。新增十九项验证，覆盖资源一致性、语义字段、未知编号、低置信度、选图失败、复核否决、七条间隔、跨群隔离、重载持久化、重复编号、路径越界和文件变化。

模拟真实 WebSocket 验证了图片消息与 ACK、失败时保留文字、文字部分送达不配图、选图过程中用户补充导致取消，以及文本 ACK 后讨论变化使图片被取消。保留既有搜索、识图和群聊调度回归。

真实模型试聊只使用合成对话和本地公开图库，没有读取真实群聊或发送 QQ 消息。最终样本在庆祝和滑稽场景选择了具体图片，对明确不要图片、认真低落和没有贴切抱抱候选的场景保留文字。实际 NapCat 的 can_send_image 只读接口返回支持；真实 QQ 图片投递尚未人工联调，自动测试中的发送与失败使用模拟 WebSocket。选图的主观贴切程度仍需群内反馈，不能由接口成功或自动测试通过推定每次都自然。
