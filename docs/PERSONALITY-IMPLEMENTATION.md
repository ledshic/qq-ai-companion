# 模块化人格首版实施记录

日期：2026-10-26。状态：代码已实现，默认关闭新模式，真实模型效果待评估。

## 本版行为

语境分析器提供当前互动的意图、认真要求、调侃限制和依据。固定规则据此形成只读表达计划，文字、识图和配图使用同一任务的计划。身份、事实边界、工具权限、参与预算及发送确认继续由现有代码控制。

| 场景 | 行为 |
|---|---|
| 认真提问 | 先回答实际问题，按问题决定解释长度 |
| 明确表达困扰 | 支持回应，停止调侃，跳过自动配图 |
| 明确要求认真或停止调侃 | 限制玩笑；即使互动意图为 unknown，也保留明确限制 |
| 双方接梗 | 保留原角色卡的社交表演与现实核实边界 |
| 分析失败或资料不足 | 回到原有自适应规则，不追加分析重试 |
| 单图请求 | 先确定实际图片任务，再做文字语境分析；采用停止调侃的保守计划，不从文字推断图片适合玩笑 |
| 空 @、暖场 | 本地形成简短应声或闲聊计划，不调用语境分析器 |
| 清空记忆等固定响应 | 不触发人格分析，沿用原命令行为 |

自动配图与明确请求图片分开。限制自动配图时，只有当前请求通过发图意图的初步筛选才会进入原有语义选择与复核；关键词本身不构成发送批准。频率和送达检查继续生效。

## 代码分工

| 文件 | 作用 |
|---|---|
| `src/context-analysis.ts` | 有限枚举与依据校验、匿名分析输入、输入版本摘要、独立分析请求 |
| `src/personality-policy.ts` | 从观察形成计划的纯函数；冲突优先级为支持回应、明确停止或认真要求、普通场景；图片任务另加保守限制 |
| `src/personality-runtime.ts` | 校验并复用观察；按任务产生冻结计划，无跨轮人格状态 |
| `src/conversation.ts` | 在现有并发名额内编排分析，给生成与媒体路径传递只读计划 |
| `src/group-judge.ts`、`src/follow-up.ts` | modular 下在既有请求中返回观察；观察字段无效不破坏有效的参与结果 |
| `src/persona.ts`、`config/personas/dafeiyu/` | 保留原卡，拆出可信固定模块和本轮表达模块；保留原场景规则作为基础 |
| `src/deepseek.ts`、`src/vision.ts` | 按本轮计划构建提示，保持原返回协议；工具循环和重复短句改写不重复分析 |

输入摘要绑定当前请求、目标、触发消息、实际群快照及个人历史；额外的参与原因和表达计划不参与版本计算。摘要只在本地校验，不发送给模型。不同输入、群或目标的观察不能复用；不匹配时回到 neutral，不补发分析。

## 配置与成本

在本地 `.env` 中设置 `PERSONALITY_MODE=modular`，重启 Node bot 生效。设为 `legacy` 并重启即可回退。未知配置值会使启动失败，避免拼写错误导致静默切换。示例配置默认 legacy，本次没有修改实际 `.env` 或重启运行中的机器人。

明确呼叫、旧随机插话和图片请求最多增加一次独立分析，超时上限 3 秒，不重试。接续和主动参与复用原判断请求中的观察；失败或 unknown 不追加请求。扩展判断结果的 token 上限为群参与 650、接续 550；发送前复查保留原上限 400、256，不要求重新分析。

原图下载与校验仍由识图模块处理。本版在编排层确定图片路径后、下载前形成计划，因而失效图片也可能产生一次文字分析请求。这与初版文档“校验成功后分析”的顺序不同，换取生成器只读计划的统一接口；分析器从不接收图片或下载地址。

## 验证与边界

新增 11 项测试，覆盖伪造依据、字段类型、冲突优先级、观察失效、超时、父任务取消、并发隔离、工具轮次、判断结果复用、真实识图适配器的模拟请求及暖场。原有测试继续验证发送确认、个人历史、图片与工具边界。

运行结果：类型检查通过，全量 180 项测试通过，离线回放与差异空白检查通过。最后的提示词措辞调整后再次通过类型检查与 11 项人格专项测试。全量测试需要本机临时监听端口，以运行模拟 WebSocket 服务；不连接 QQ，不使用真实模型密钥。

本版未加入长期关系、情绪分数、跨轮人格存储或人格影响主动参与概率。未进行 DeepSeek 或 Grok 的真实模型对比，不能据程序测试声称语气更自然或分析时延已经达标。默认开启新模式前，仍需按设计中的匿名场景评估输出与成本。

文档自查已核对标题、用词、段落、标识符和源码中的配置及请求上限。

## 启用与真实模型试验

2026-10-26：按用户要求将本地 `.env` 切换为 modular，仅重启 Node bot。最终启动日志确认模式启用、OneBot 已连接；只读查询返回 QQ 在线且服务正常。示例配置继续默认 legacy。

首次真实试验发现独立分析请求被 DeepSeek JSON 模式拒绝：提示中缺少 json 字样。修正后又发现模型有时直接输出观察对象，而解析器只接收 observation 包装对象。现已明确独立请求的根对象格式，同时对两种形式使用相同的字段与依据校验。补充接口回归后，类型检查和 12 项人格专项测试通过。

三组匿名合成输入实际调用当前配置的 deepseek-flash：接梗产生 play 计划，认真核实产生 explain 计划，困扰倾诉产生 support 计划；三次观察均有效，耗时分别约 992、957、652 毫秒。认真与支持计划均停止调侃并抑制自动配图。最终文字能继续玩笑，或按当前要求认真核实与倾听。

另用匿名样本验证接续判断和主动参与判断，二者均返回有效观察并形成 explain 计划，运行时日志确认 source=reused，无额外分析调用。试验未发送 QQ 群消息；这些小样本仅确认调用路径和典型行为，不代表长期自然度或时延统计。三组试验结果保存在本机忽略目录 `data/runtime/personality-smoke-results.json`，运行日志位于 `data/runtime/tsbot-modular.log`。
