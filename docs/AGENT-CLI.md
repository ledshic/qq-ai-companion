# Agent 命令行实施记录

2026-10-29。`pnpm agent:cli` 提供单次命令和 `chat` 交互式聊天，均使用正式服务 SDK。CLI 不启动服务、不创建凭据，不在本地复制模型、工具循环或会话存储。

## 连接与凭据

服务需事先运行。默认地址为 http://127.0.0.1:4320，使用 AGENT_URL 覆盖；地址校验沿用共享客户端，仅允许本机 HTTP 或 HTTPS。

凭据默认读取数据目录中的 service-owner.json。AGENT_CREDENTIAL_FILE 可指定已有设备凭据 JSON，只需包含 token 字段。CLI 不接受命令参数形式的令牌，不打印凭据内容或异常堆栈。帮助及参数检查不读写凭据，读取失败明确返回错误。

交互模式通过同一凭据调用 /me，认证失败不打开输入会话。任务归属、来源授权、模型配置、并发和超时均由原服务负责，CLI 不另建认证或权限规则。

## 交互式聊天

```sh
pnpm agent:cli chat
# 或连接已有的本人会话：
pnpm agent:cli chat <conversationId>
```

普通输入提交一条消息；未选择会话时，首条消息创建新会话。同一进程可以连续交流，下一轮模型历史由服务端读取已完成问答，客户端不把本地输出重新拼成模型历史。以 `//` 开头可发送以 `/` 开头的普通正文。

终端支持多行编辑：Enter 发送，Ctrl+J 或 Alt+Enter 换行，方向键移动，Ctrl+G 清空输入。Ctrl+X 通过正式接口取消当前任务并保留编辑内容；忙碌时按 Enter 也保留内容。粘贴、多行管道输入、按键与显示规则见[多行编辑记录](AGENT-CLI-EDITOR.md)。

单行命令按 Tab 补全命令、任务状态和筛选参数；多个候选显示在编辑区，继续输入缩小范围。补全不查询标识、不自动执行，正文和粘贴保留原有缩进规则，详见[命令补全记录](AGENT-CLI-COMPLETION.md)。

Ctrl+P / Ctrl+N 选择本次输入历史，Ctrl+O 返回原草稿；历史仅在当前编辑器内存中保存，不写入文件。输入前加空格可跳过记录，`/clear-input-history` 清空记录；上下方向键仍移动多行光标。保存上限、取回后编辑及隐私规则见[输入历史记录](AGENT-CLI-INPUT-HISTORY.md)。

| 交互命令 | 行为 |
| --- | --- |
| /help | 查看帮助 |
| /list | 列出当前认证身份可见的会话 |
| /tasks [状态] | 默认 active；可选 all 或六种具体状态；/tasks more 读取下一页 |
| /tasks [状态] --here / --conversation <id> | 限定当前或指定会话；后续 more 保持状态与会话范围 |
| /new [标题] | 创建并切换新会话 |
| /use <conversationId> | 校验会话可见性后切换，读取最近消息 |
| /history | 分页读取当前会话，展示最后 20 条消息，不显示推理 |
| /clear-input-history | 清除当前进程的输入记录和浏览快照；服务端消息继续保留 |
| /retry | 用相同正文和 clientMessageId 重试结果未确认的提交 |
| /resume [runId\|#序号] | 不带参数显示未完成任务；按标识或列表编号恢复观察，终态直接显示结果 |
| /cancel | 显式取消当前任务，展示服务返回的实际状态 |
| /exit | 退出本地聊天，不取消已接受任务 |

每次只观察一个任务。当前任务尚未结束或提交结果未确认时，普通输入不会取代它，/new 和 /use 也不会改变当前会话。可继续查看列表、历史和帮助，或通过 /cancel、/resume、/retry 处理当前任务。

选择已有会话不会自动接管其他设备的未完成任务。可先 `/tasks` 发现任务，再 `/resume #序号` 观察，也保留完整任务标识入口。列表只显示摘要，选择后重新查询身份和状态；终态不重新执行。分页、编号与权限规则见[任务列表记录](AGENT-CLI-TASKS.md)。其他设备提交的新消息仍按既有服务规则取代同会话未完成任务。

`--here` 和 `--conversation` 互斥。切换当前会话不改变已经打开的分页范围，重新指定筛选才清除旧编号。单次命令、筛选与分页的完整参数见[会话筛选记录](AGENT-CLI-TASK-FILTERS.md)。

状态支持 queued、running、completed、failed、cancelled、interrupted，保留 active 和 all。用 `/tasks failed --here` 查看当前会话失败项，终态只读，不会重新执行；完整规则见[具体状态筛选](AGENT-CLI-TASK-STATES.md)。

## 重试、取消与退出

提交前输出 clientMessageId 和会话标识。网络或服务错误导致接受结果不确定时，保留原正文和标识，禁止继续提交新消息，等待用户 /retry 或退出；不自动生成另一条逻辑消息。确定的请求拒绝会显示错误，可继续操作。

接受后保留 runId，通过 SDK 订阅任务输出快照，逐片段显示未提交草稿，完成后展示服务确认的最终回答。观察失败不再次提交消息，也不假定任务结束；用户可以 /resume 同一任务或 /cancel。正常观察中的任务不会建立第二个结果观察器。服务失败、中断和取消均按实际终态显示，不伪造成助手成功回答。

/exit、Ctrl+C、Ctrl+D 或进程 SIGTERM 只结束本地观察，不调用远程取消接口。标准输入结束时，先处理已经读入的命令，再关闭；Ctrl+C 可以立即退出。本地仍有未确认提交时，退出前打印重试标识，重新连接后用单次 send 的相同标识和正文确认结果。

退出、取消或切换观察后，旧请求的迟到结果不再写入终端会话。只在获得服务端取消结果后结束当前任务的本地观察；未确认的取消不会被当成成功。服务端本身继续负责防止取消后的迟到结果写入数据库。

## 单次命令

| 命令 | 行为 |
| --- | --- |
| status | 查询正式服务状态 |
| conversations | 分页列出当前身份可见会话 |
| tasks [状态] [--conversation <id>] [--before <runId>] [--limit <n>] | 输出一页摘要及 nextCursor，默认 active；支持六种具体状态，不自动翻页 |
| new "标题" | 创建拥有者直聊会话 |
| send <conversationId> "正文" [clientMessageId] | 提交一次消息，先输出重试标识，再输出接受结果 |
| run <runId> | 查询保存的执行状态和结果 |
| cancel <runId> | 显式取消执行 |
| watch [afterEventId] | 从指定位置观察事件；Ctrl+C 停止观察 |
| sources <conversationId> | 查看会话的授权来源 |
| grant-sources <targetId> <sourceId> ... | 整体替换来源列表，需管理拥有者权限 |
| clear-sources <conversationId> | 清空来源列表 |

多词正文和标题使用 shell 引号。来源授权会整体替换列表，由服务检查归属、数量和权限。GET 的有限重试沿用 SDK，POST 不暗中重试。watch 可保存最后的 eventId，重新连接时作为参数传入；位置失效应重新读取快照。

## 输出与范围

单次命令的数据为逐行 JSON，chat 使用可读文本和终端提示符。交互命令的错误写到标准错误并保留会话；进入前的认证或请求失败返回退出码 1，参数错误为 2，正常退出或用户中断为 0。

交互模式不保存本地输入历史文件，不默认展示推理，并过滤服务文本中的终端控制序列。实际推理与来源仍通过原服务管理。当前支持多行编辑和真实模型增量输出；终端草稿在有界区域内刷新，不逐片段追加滚动行。取消或失效时清空草稿，不写入消息历史；已有终端记录不能保证撤回。没有自动重连或后台守护进程，断线后用 /resume 恢复。
