# 参考文本驱动的通用事件模型

日期：2026-10-26。状态：已实现，继续 observe。

## 本次修订

上一版虽然把休假拆到独立模块，仍然固定了主题类型、复工字段和假期后续规则。本版删除该主题模块，所有生活事件使用同一结构。休假、考试、旅行和个人计划的理解方式保存为参考文本，模型依据原文与参考提出结构化建议。

当前协议以 `src/events/domains/event.ts` 为准。原设计中的 VacationEvent、resumeOn 和 vacation_followup 是历史草案，不再用于新事件提取。

## 三层分工

| 层次 | 保存内容 | 修改方式 |
|---|---|---|
| 通用引擎 | 来源、任务、版本、去重、存储、保留期限、观察 | 新增主题不改这里 |
| 通用事件协议 | 原文证据、陈述性质、时间点、区间、里程碑、关注建议 | 新增时间运算或数据能力时才扩展 |
| 参考文本 | 不同语境的理解示例、适合关注的时机、不能推断的事实 | 修改或增加 Markdown，无须注册主题插件 |

主题名、摘要、里程碑标签和交流建议都是资料，代码不按其文字执行分支。权限与是否发送不交给参考文本；当前引擎仍无发送接口。

## 通用结构

| 字段 | 含义 |
|---|---|
| topic / summary | 开放主题与事实/计划摘要，不是枚举或可执行指令 |
| assertion | 区分明确陈述、愿望、假设、转述和未知；只把明确陈述保存为事实/计划 |
| statement | 实际提供的来源别名和逐字原句 |
| startOn | 有依据的时间点，不要求同时知道持续时长 |
| period / durationDays | 可计算的自然日区间和原文持续天数 |
| anchors | 开放语义的里程碑及其来源时间；可声明通用的先后约束 |
| followup | 选择已有时间锚点，提供有依据的交流建议，并区分明确或推断性质 |

例如“明天休两天，周一上班”可以形成区间与上班里程碑；“下周三考试”可只有时间点。代码不会自动把区间结束解释成复工或考试结束，也不会仅因某个主题出现就创建关注事项。

没有日期的明确计划仍可以保存，关注建议无法解析到可靠日期时不产生到期事项。重复陈述可引用同一 existing 事件；更正校验来源、目标版本与清空版本，不按“最近一条”猜测目标。

## 参考文件

- `config/event-memory/references/README.md`：共同理解原则，计划与事实、未知信息、后续交流机会。
- `config/event-memory/references/life-events.md`：休假、学习、项目、旅行和兴趣活动示例。

加载器读取目录内所有 Markdown，按文件名排序并限制总长度。重启 Node bot 后生效，避免一次请求读到半更新内容。参考来自受版本管理的本地文件；模型不能在线修改这些文件。

日历运算仍由代码执行。模型只能引用原文的时间片段，不能直接填写计算后的日期；代码检查来源、支持的日期语法、区间约束和关注锚点范围。语义分类是否正确仍需模型样本验证，字段校验不能代替语义正确性。
