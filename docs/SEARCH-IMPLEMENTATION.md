## 使用与配置

运行环境设置 `WEB_SEARCH_ENABLED=true`，复用 `DEEPSEEK_API_KEY`，无需新增搜索服务或复制 AstrBot 密钥。示例配置默认关闭，当前运行配置已开启。关闭后重载 TS 进程即可停用，不需重启 NapCat。

参考暂停项目的 `web_search=true`、`websearch_provider=deepseek` 配置与搜索工具实现，使用 [DeepSeek 官方搜索接口](https://api-docs.deepseek.com/guides/search/)。没有迁移其插件框架。模型按问题决定是否调用；用户可以直接说“帮我联网搜索……”。

新项目默认隐藏链接，本次选择在每次搜索回答后附最多六个来源（两次搜索各三个）的标题和普通链接，便于立即核对，也让追问能从已送达个人历史中找到依据。历史仍按本群、本用户隔离，最多九轮、三十分钟。没有另建永久搜索数据库；历史过期后不会保留依据。

## 限制与失败处理

- 每条生成任务最多两次搜索，每次最多三个结果，等待上限八秒。没有自动重试，避免限流时增加等待和费用。
- 查询最长一百二十八个字符；不发送整段群上下文，提示模型只用公开信息关键词。搜索词由模型提取，仍会交给外部服务处理。
- HTTP 响应（服务返回状态）异常、网络错误、超时、非法结构或超过二百五十六千字节的响应，都返回失败；有效空数组单独视为无结果。
- 全部搜索失败或没有结果时使用固定说明，不能采用模型编造的成功结论；部分成功时保留来源并标明未核实部分。用户取消会继续向上传播，停止生成和发送。
- 网页摘要只作为不可信资料交给模型。正文最多每条五百字符；链接只接受 HTTP/HTTPS，不接受带用户名密码的地址，移除常见追踪参数，不下载链接对应页面。
- 搜索日志只记录状态与结果数量，不写查询、网页内容、密钥或服务错误正文。模型输出和网页本身仍可能有错误，来源摘要不能证明已阅读全文。

搜索工具返回的结构包含标题、链接、摘要、可用的发布时间和检索时间；回答与个人历史保留标题和链接。实际发送仍经过 A–C 的时机检查和送达确认，取消或未送达内容不计入个人历史。
