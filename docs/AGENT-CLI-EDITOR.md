# CLI 多行编辑与草稿展示记录

2026-10-29，面向使用者和仓库维护者。交互式 CLI 已支持多行编辑，在同一终端区域更新未提交草稿，并保留认证、取消、显式重试和任务恢复。使用原有 `pnpm agent:cli chat`，不增加运行依赖、服务接口或数据库结构。

## 终端操作

TTY（可交互终端）中，Enter 发送当前完整输入，Ctrl+J 或 Alt+Enter 插入换行。发送保留缩进与空行；多行中的 `/cancel` 等文字作为正文，不拆成命令执行。单行命令继续按原规则处理，单行普通正文以 `//` 转义开头的 `/`。

| 按键 | 行为 |
| --- | --- |
| 左右方向键、Backspace、Delete | 按完整文字单元移动或删除，不拆开组合 emoji 和重音字符 |
| 上下方向键 | 在可视行之间移动，尽量保留原列位置 |
| Home / End、Ctrl+A / Ctrl+E | 移到当前逻辑行首、行尾 |
| Ctrl+U / Ctrl+K | 删除到当前逻辑行首、行尾 |
| Tab | 单行命令中补全；普通文本、多行或转义正文中插入两个空格，见[补全记录](AGENT-CLI-COMPLETION.md) |
| Ctrl+G | 清空尚未发送的输入 |
| Ctrl+X | 通过正式取消接口取消当前任务，保留正在编辑的内容 |
| Ctrl+C | 退出本地观察，远程任务继续运行 |
| Ctrl+D | 空输入时退出；有输入时向前删除，不发送内容 |

任务运行或前一次输入处理期间，Enter 不会丢弃下一条编辑内容。取消或完成后可继续编辑并发送；`/cancel` 仍可使用。未确认的提交继续要求 `/retry`，断线继续使用 `/resume <runId>`，不会自动再发一条消息。

进入终端编辑前先认证。退出或输入异常时移除监听器，恢复进入前的原始输入模式，并关闭粘贴标记模式；不保存本地编辑历史文件。未发送内容在退出时丢弃。

## 粘贴与输入上限

支持 bracketed paste（用开始、结束标记包住粘贴内容）的终端会先收集整段文本，保留多行并等待 Enter，粘贴中的命令不立即执行。标记和中文字节跨数据片段到达也能正确处理。超出 8000 字符的插入整次拒绝，保留原输入，不发送截断版本。

Shift+Enter 的编码因终端而异；已经支持两种常见编码，建议统一使用 Ctrl+J。终端不提供粘贴标记时，可通过管道使用下述显式多行模式。显示宽度按常见中文与 emoji 计算，特殊字体的字符占位仍可能有差异。

## 管道与重定向输入

非 TTY 输入沿用逐行命令；多行消息使用显式模式：

```text
/edit
  第一行保留缩进
/cancel
//send
// comment
/send
```

以上只提交一条消息，正文中的 `/cancel` 不执行，`//send` 表示字面 `/send`，`// comment` 保持原样。`/discard` 丢弃编辑；需要正文 `/discard` 时写 `//discard`。更多前导斜线可逐层转义这两个结束命令。

编辑中其他命令都作为正文。发送时仍检查当前任务和未确认提交，忙碌时保留多行内容；超限后必须丢弃并重新输入，不允许发送部分内容。输入结束不会自动发送未确认的多行编辑。

## 草稿与稳定输出

终端草稿采用完整快照原位替换，显示“草稿·未提交”，长草稿仅显示尾部。编辑区围绕光标显示，区域高度随终端大小限制，避免每个模型片段都增加一条滚动记录。缩放和服务通知会重新绘制，保留文字与光标。

完整回答和发送内容只在普通输出中记录一次。失败、取消或断线清除活动草稿；已发送到终端的文字仍可能被终端保存，不能保证撤回。管道输出继续追加片段并明确标记替换、清除或连接中断，不写入用于屏幕刷新的控制序列。

草稿仍来自原有 SDK 任务订阅，不进入数据库或下一轮历史。来源授权检查、最终提交、取消后的迟到结果过滤，以及恢复时的拥有者校验均由原有服务流程负责。
