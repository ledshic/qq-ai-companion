# TS bot 单图理解实施记录

2026-10-23：D 阶段的单图理解已完成。当前 unified 模式支持明确呼叫时附带或引用的一张图片；普通群消息、连续对话中未再次明确呼叫的图片、主动插话和暖场不自动读图。D 阶段剩余表情包发送。

## 使用方式

- 把 @机器人、问题和一张图片放在同一条消息里，例如询问截图中的文字或图片内容。
- 引用一条单图消息，同时 @机器人或使用句首称呼，提出问题。引用必须能通过 NapCat 查到，且群、消息编号、发送者有效。
- 只有 @ 和一张图片也可以，默认用中文简要描述。一次附带多图，或同时附带和引用图片，会请用户只选一张。
- 图片和请求可分开发送：同一用户在九十秒内发图后，再明确呼叫并提出看图请求，平台用语义判断确认是否指向该图，再查询原消息。若其他人插入了更新的图片、时间已过或进程已重载，请显式引用或重发。

## 配置与实现

新项目的 Flash 提供商声明图片能力，图片压缩最长边为 1280，没有指定独立的图片描述服务。本次复用现有 DeepSeek 密钥，使用 `VISION_ENABLED=true`、`VISION_MODEL=deepseek-flash`；示例配置默认关闭。

图片作为真实的图片内容块提交给模型，不将文件名或群友的描述当成识别结果。[DeepSeek 官方图像接口](https://api-docs.deepseek.com/guides/vision/)说明了图片输入格式；本次另用真实调用验证了当前模型支持。

新增 sharp 图片库负责读取、尺寸校验和缩放。图片来源只接受 QQ 图片消息的 HTTPS 地址，限制到 qpic.cn 及 multimedia.nt.qq.com / multimedia.nt.qq.com.cn；不读取容器或宿主机路径，不下载任意聊天链接，不跟随重定向，不把 API 密钥带到图片站点。

没有可用地址时通过 OneBot（机器人与 NapCat 的通信接口）的 `get_image` 查询文件标识。地址返回 403、404 或 410 时最多刷新一次，整个获取流程共用八秒期限。NapCat 官方[文件说明](https://napneko.github.io/develop/file)说明了图片地址过期及刷新方式。仅返回本地路径的图片会提示获取失败，不尝试读取路径。

## 失败、取消与保留内容

| 环节 | 处理 |
|---|---|
| 引用无法确认、没有图片、多图或能力关闭 | 明确提示原因，不提交图片模型 |
| 下载超时、网络错误、超大或不支持的内容 | 提示获取或读取失败，不让文字模型猜图 |
| 识别服务异常、限流、超时、异常 JSON 或空回答 | 提示识别失败，不声称已经看懂 |
| 用户补充消息、任务被取代或断线 | 传播取消；迟到结果不发送、不计入历史 |
| 讨论在识别期间变化 | 经过既有发送前检查，过时分析可被放弃 |
| 发送失败 | 不把未送达分析写进个人历史 |

下载和处理后的图片各限八 MiB（约八百四十万字节），解码限一千六百万像素，最长边缩到 1280；解码转换另设五秒处理限制，识别请求限三十秒，不自动重试模型。JPG、PNG、WebP、GIF 按实际内容校验，不相信扩展名或服务声明的文件类型；动态图只分析首帧，并在回答中说明。

TS 进程只在任务内存中持有图片，剥离图片元数据后提交，不写原图临时文件。NapCat 自身可能维护附件缓存，本次不改其缓存机制。图片地址、访问参数和 base64 图片编码不进入群上下文、模型讨论资料或个人文字历史，日志只记录成功或失败阶段。

只有实际送达的回答和“本次有图片”的文字标记进入既有个人历史，后续追问可参考分析，不能重新查看原图细节。再次细读请重新附带或引用图片。图片中写着的指令按待分析内容处理；仍无法保证模型对每张图的判断都正确。

## 验证结果

123 项自动测试全部通过，类型检查与差异空白检查通过。保留原有 107 项回归，新增 16 项覆盖：

- 附件数量、签名地址不进入上下文、有效字节解码与 1280 缩放、元数据移除、动态图首帧。
- 不安全地址、重定向、本地路径、过期链接刷新、大小与像素限制、损坏或不支持格式。
- 下载失败、识别失败、超时、取消、空或畸形模型响应、密钥和服务错误不泄露。
- 模拟 WebSocket 下当前图、文件标识、同群引用、错群或错消息引用、多图拒绝、重复事件、禁用能力。
- 用户补充内容使旧任务失效、发送前讨论变化、发送失败不写历史、普通或连续对话图片不自动读图。

真实联调使用自制测试图，经过实际图片校验和缩放后调用真实 DeepSeek Flash，正确识别蓝色正方形、红色圆形和数字 42。QQ 下载由测试替代，真实 QQ 图片下载与群内发送尚未做人工联调；没有把真实群图片上传给模型，也没有向 QQ 群发送测试消息。

测试图与模型回答另存为验证附件。此次验证能证明模型接口和本地处理可用，不能证明所有 QQ 附件、细小文字或复杂截图都可正确识别。


## 分开发图修复记录

测试群的实际顺序为单独发一张图，十二秒后 @ 并问“看看这是什么”。旧版只处理同条附件或显式引用，文字模型只收到图片消息标记，所以如实说看不到内容；不是图片地址失效。

现在群讨论只额外保存图片数量和既有消息编号，不保存签名链接或原图。候选取本群最近图片，必须由当前提问者发送且不超过九十秒；模型先确认当前请求确实指向该图，才通过 `get_msg` 查询原消息，并严格核对群、发送者和消息编号。普通问题、其他人的图片、别群图片和未明确呼叫不会触发读取。取消、查询失败、多图和失效图片仍沿用原来的失败处理。

意图判断只看当前 question 字段，当前消息不再重复塞入历史讨论，避免把旧看图请求当成新请求。模型判断超时或异常时不读取之前的图片；此判断是语义推断，不保证完全没有误判。

全量一百四十项测试、类型检查通过，新增分开发图的调度及 WebSocket 验证，覆盖十二秒后提问、普通问题、过期、跨人跨群、原消息错配、多图、判断失败和取消。测试群原图片已真实查回、下载并解码，未保存或上传给模型。另用合成上下文调用真实意图模型，确认“看看这是什么”要求识图，而普通算术、停止看图和请求生成自拍不读取旧图。没有向 QQ 群发送测试消息。
