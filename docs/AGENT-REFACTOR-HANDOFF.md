# 通用个人 Agent 重构交接与后续计划

更新日期：2026-10-28。本文面向后续在本仓库工作的 Codex，先读当前状态，再核对实际 Git 改动。

## 产品与实施方向

以通用个人 Agent 为主体，保留 Web/CLI 方向、认证 API、持久任务和客户端能力。QQ 可以可恢复地归档，不要求保留旧群聊行为。每期必须可运行、可验证，不能只移动目录后宣称解耦。

不引入无实际用途的框架、插件系统或空抽象。旧 QQ 数据不自动导入新身份体系；迁移前必须提供身份映射、备份和验证方案。

## 接手顺序

1. 阅读本文、根 README、各期实施记录，再按任务读取源码。
2. 检查适用的 AGENTS.md、Git 状态、暂存及未暂存差异，保护已有工作。
3. 每期分别验证、提交，记录结果和实际限制。
4. 依赖和命令以 package.json 为准，不自动安装工具，不请求真实模型或 QQ，不用真实用户库跑测试。

## 当前职责与依赖方向

| 边界 | 职责与约束 |
| --- | --- |
| 接入层 | HTTP/CLI 输入输出、认证与协议转换；不实现人格、召回或工具循环 |
| 应用层 | 提交、取消、查询、任务生命周期和消息提交；不实现供应商协议 |
| Agent 核心 | 模型和工具循环、预算及结束条件；不依赖 QQ、HTTP 或 SQLite |
| 能力层 | 可选来源召回与人格表达；不能决定认证身份或全局任务队列 |
| 基础设施 | 模型 API、数据库和网络实现；不决定群聊参与策略 |
| 宿主 | 配置、注入、启动与关闭；RunHost 管并发、总超时和持久化 |

工作台已使用中立消息契约及通用执行器。来源召回默认关闭；开启后只读已完成用户消息，默认限制在当前会话，跨会话需拥有者显式授权。人格只提供可选表达提示。共享会话仅实现能力层的保守过滤规则，服务尚不创建共享会话。

三期未做用户画像提取、向量检索、QQ 身份绑定、旧数据迁移或新的记忆写入副本；没有将旧群聊调度和长期事件系统接回活动服务。

## 四期：归档旧 QQ 与清理遗留

下一步先分析活动服务依赖图，确定旧群聊调度、暖场、观察窗口、表情投递和 QQ 适配代码的归档边界。先提取仍被服务使用的基础设施，再归档其余内容；不能整份复制核心。

归档须同时处理旧脚本、测试入口、配置和文档。归档代码应保留可恢复的 Git 历史，并退出默认类型检查和测试扫描。必要的旧数据兼容测试仍保留在活动代码中。

验收要求：

- 活动服务依赖图不触及归档代码；核心不引用 QQ 编码、观察窗口或传输协议。
- 默认配置、文档与运行命令面向个人 Agent；不保留会误启动旧宿主的默认命令。
- 数据路径、数据库和拥有者凭据不改、不删除；`bot.lock` 和 API `qq` 字段本期保留，未来另作兼容迁移。
- 核心、API、任务、客户端及浏览器验证通过，交付说明列出实际改动、命令、限制和提交 ID。
