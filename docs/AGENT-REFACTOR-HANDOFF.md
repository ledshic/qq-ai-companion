# 通用个人 Agent 重构交接与后续计划

更新日期：2026-10-27。本文面向后续在本仓库工作的 Codex。

## 1. 已确认的产品与实施方向

用户希望彻底整理架构，以通用个人 Agent 为主体。QQ Bot 可以暂时归档或丢弃，不要求保留旧群聊行为。优先选择可运行、可验证的分期交付，不要再次只移动目录或改名后宣称完成解耦。

当前阶段保留 Web/CLI 方向，以及已有认证 API、持久化任务和客户端能力。不要为“标准架构”引入不必要的框架、插件系统或空抽象。本文定义的是目标职责，目录命名可按实施证据调整。

## 2. 接手时首先执行

1. 阅读本文、根 README、`docs/MULTI-CLIENT-PHASE-B.md`，再按任务读取相关源码。旧架构文档含 QQ 历史语义，不能当作必须兼容的目标。
2. 检查适用的 AGENTS.md、`git status --short`、已暂存和未暂存差异，确认这份快照是否仍有效。不要重置、覆盖或一并提交不属于当前任务的改动。
3. 先复核一期并完成可运行环境下的验证，提交一期后，再开始下一阶段。各期分别提交并记录验证结果。
4. 依赖和测试命令以当前 package.json 为准；不要自动安装工具，不要在测试中请求真实模型或真实 QQ。

## 4. 目标职责与依赖方向

| 边界 | 负责 | 禁止或应避免 |
|---|---|---|
| 接入层 | HTTP/CLI 输入输出、认证、协议转换 | 实现人格、召回、工具循环 |
| 应用层 | 提交/取消/查询、任务生命周期、会话历史提交 | 模型供应商协议、直接实现工具 |
| Agent 执行核心 | 上下文准备、模型调用、工具执行循环、预算和结束条件 | QQ、HTTP 状态码、SQLite 实现 |
| 能力层 | 可选记忆、人格、工具注册与策略 | 渠道连接、全局任务队列 |
| 基础设施 | 模型 API、数据库、文件和网络实现 | 决定群聊参与或人格表达策略 |
| 宿主 | 配置、注入、启动与关闭 | 具体会话业务决策 |

宿主可以依赖所有具体实现；核心只通过小而有实际用途的契约使用外部能力。任务生命周期与一次推理执行分开：RunHost 管排队、取消、超时和落库，执行核心管模型与工具循环。避免为 Web/CLI/未来渠道再复制一套核心。

## 5. 二期：提取通用执行核心与模型/工具契约

这是一期验证并提交后的首选工作范围。

首先调查：

- `src/runtime/service/host.ts`：队列、AbortController、超时、迟到结果保护；
- `src/channels/console/generator.ts`：工作台生成入口及身份提示；
- `src/cognitive/models/deepseek.ts`：工具循环、回复处理、来源与搜索状态；
- `src/cognitive/models/model-request.ts`：供应商 HTTP；
- `src/tools/builtin.ts`、`search.ts`：同步工具与异步搜索的不同路径。

实施建议：

1. 定义最小模型契约：消息、工具描述、模型返回的文本或工具调用、取消信号。供应商适配器负责协议转换；不在核心使用 DeepSeek 响应原始结构。
2. 将模型与工具循环放入通用执行器，注入模型和工具注册表。工具支持异步执行、取消和上下文；不要让新增工具要求修改供应商分支。
3. 明确最大轮次、调用数量、结果体积和超时；保留搜索失败、无结果、来源引用的可解释行为。
4. 将工作台生成入口接到执行器。RunHost 保留任务编排与持久化，避免同时存在两套超时/并发所有权。
5. 使用中立的会话消息契约，解除活动服务对旧 QQ 会话上下文的类型依赖。保留现有推理展示功能，但推理内容不能混入下一轮模型历史。

验收：使用假模型完成文本返回、一次/多次工具调用、工具失败、未知工具、预算耗尽、取消；取消后不得继续调用工具或提交迟到结果。增加一个异步测试工具只需注册实现。已有 API 和任务测试继续通过。无需新增真实工具或第二家供应商来证明抽象成立。

## 6. 三期：身份、记忆与人格边界

调查入口：`runtime/chat-scope.ts`、`memory/events/runtime.ts`、`personal-recall.ts`、`archive.ts`、`runtime/conversation/reply-context.ts`。

- 明确定义 owner、conversation、participant、channel 和数据可见范围。私聊/共享会话应是显式元数据，不通过数字 ID 或 `private:` 字符串推断权限。
- 新服务短期历史继续由服务存储管理，避免另建一份同用途会话状态。
- 长期记忆作为可选能力接入执行前的上下文准备；先定义授权、来源、跨会话可见性，再决定旧事件系统可复用部分。
- 人格提供可选表达计划或提示片段，不决定认证、权限、工具执行和记忆可见范围。
- 旧 QQ 数据保留，默认不导入新身份体系。若要迁移，先提供可审阅的映射、备份和验证方案，再执行迁移。

验收：非数字身份可用；不同 owner/会话间的召回隔离得到测试；能力关闭或失败有明确降级；无依据的长期记忆不得进入提示。不要把所有人格和记忆逻辑塞回执行器。

## 7. 四期：归档旧 QQ 与清理遗留

用户已允许归档或丢弃 QQ，默认选择可恢复归档；不必保留旧群聊功能的行为兼容。

- 在二/三期完成必要契约替换后，按依赖图确认哪些旧群聊调度、暖场、观察窗口、表情投递及 QQ 适配代码不再被活动路径引用。
- 明确归档边界，同时处理旧脚本、测试入口、配置和文档；归档代码不应继续被默认构建或测试扫描。
- 不要仅把全部 src 移到 legacy 后复制一套核心。先提取确实共享的基础设施，再移除反向引用。
- 可以保留有价值的行为测试作为迁移依据，但不要让新架构为了满足旧群聊测试重新引入 QQ 假设。
- 最后再考虑 `bot.lock`、API `qq` 字段和项目命名的迁移；涉及公开协议或数据路径时必须说明兼容策略。

验收：活动服务依赖图不触及归档代码；默认配置和文档面向个人 Agent；核心不引用 QQ ID 编码、群聊观察窗口或传输协议。

## 8. 各期共同完成标准

- 每次先固定本期行为和退出条件，避免无限扩大范围。
- 小步调整，保护现有工作；不自动安装依赖，不操作真实账户，不用真实用户数据库跑测试。
- 测试优先覆盖跨边界行为、取消/超时/恢复、数据隔离和失败路径，不为纯搬文件写镜像测试。
- 运行与变更匹配的类型检查和测试。改契约时补客户端检查；无关 UI 不改、不重新设计。
- 更新当前架构说明，区分已实施、已验证、未验证和后续规划。
- 每期交付说明实际变更、验证命令与结果、剩余限制和提交 ID。不要把宿主隔离等同于全部架构重构完成。
