# 通用个人 Agent 重构交接与后续计划

更新日期：2026-10-29。本文面向后续在本仓库工作的 Codex，先读当前状态，再核对实际 Git 改动。

## 产品与实施方向

以通用个人 Agent 为主体，保留 Web/CLI 方向、认证 API、持久任务和客户端能力。QQ 可以可恢复地归档，不要求保留旧群聊行为。每期必须可运行、可验证，不能只移动目录后宣称解耦。

不引入无实际用途的框架、插件系统或空抽象。旧 QQ 数据不自动导入新身份体系；迁移前必须提供身份映射、备份和验证方案。

## 接手顺序

1. 阅读本文、根 README、各期实施记录，再按任务读取源码。
2. 检查适用的 AGENTS.md、Git 状态、暂存及未暂存差异，保护已有工作。
3. 每期分别验证、提交，记录结果和实际限制。
4. 依赖和命令以 package.json 为准，不自动安装工具，不请求真实模型或 QQ，不用真实用户库跑测试。

## 当前职责与依赖方向

| 边界 | 职责与约束 |
| --- | --- |
| 接入层 | HTTP/CLI 输入输出、认证与协议转换；不实现人格、召回或工具循环 |
| 应用层 | 提交、取消、查询、任务生命周期和消息提交；不实现供应商协议 |
| Agent 核心 | 模型和工具循环、预算及结束条件；不依赖 QQ、HTTP 或 SQLite |
| 能力层 | 可选来源召回与人格表达；不能决定认证身份或全局任务队列 |
| 基础设施 | 模型 API、数据库和网络实现；不决定群聊参与策略 |
| 宿主 | 配置、注入、启动与关闭；RunHost 管并发、总超时和持久化 |

工作台已使用中立消息契约及通用执行器。来源召回默认关闭；开启后只读已完成用户消息，默认限制在当前会话，跨会话需拥有者显式授权。人格只提供可选表达提示。共享会话仅实现能力层的保守过滤规则，服务尚不创建共享会话。

三期未做用户画像提取、向量检索、QQ 身份绑定、旧数据迁移或新的记忆写入副本；没有将旧群聊调度和长期事件系统接回活动服务。

## 后续迭代范围

CLI 和来源授权管理界面均已完成，复用正式认证和执行流程。工作台在对话标题旁提供来源授权入口；普通设备只读，管理设备保存时检查授权版本，冲突或结果不确定时必须重新加载，不自动扩大授权或重试写入。

交互式 CLI 已实现，每次观察一个任务；/exit、Ctrl+C 或输入结束不取消服务端任务，/cancel 才调用正式取消接口。提交结果未确认时保留原标识并等待显式 /retry，观察失败可 /resume，不另建模型和历史流程。

真实流式输出已完成：模型片段进入内存草稿，通过按任务订阅的完整快照显示到 Web 和交互式 CLI。认证、取消、来源变更和最终提交继续由服务检查；草稿不保存到数据库或下一轮历史，断线后按最新快照恢复。Web 有限重连，CLI 用 /resume 显式恢复，具体限制见流式记录。

CLI 多行编辑与草稿展示已完成：Enter 发送，Ctrl+J 或 Alt+Enter 换行；终端草稿原位替换，保留光标和未发送内容；Ctrl+X 取消当前任务但保留输入。管道使用 /edit、/send、/discard 明确多行边界。任务恢复继续用 /resume，不增加自动提交或新凭据流程。

CLI 任务列表与恢复入口已完成：/tasks 查询未完成任务，/tasks all 查看全部，/tasks more 分页；/resume 不带参数显示候选，/resume #序号 重新查询后恢复观察。新增 GET /runs 摘要接口和 SDK runs 方法，按拥有者隔离，不携带正文或草稿；恢复和取消继续使用原流程。列表不是执行队列副本，也不自动重跑终态任务。

任务会话筛选与单次命令已完成：交互式使用 --here 或 --conversation，翻页保持原会话范围；单次 tasks 命令输出一页 JSON 与 nextCursor，支持状态、会话、游标和页长。服务校验会话与游标归属，SDK 校验返回项范围；认证、取消和来源授权规则保持原流程，不创建新的执行或凭据体系。

任务具体状态筛选已完成：支持 queued、running、completed、failed、cancelled、interrupted，保留 active、all 和原默认值。状态与会话可组合，more 沿用两项条件；SDK 校验状态匹配，恢复时仍重新读取最新状态，不自动重跑终态任务。认证、取消与来源授权检查继续使用原流程。

交互式 CLI 命令补全已完成：单行命令 Tab 补全命令、任务状态及筛选参数，候选在有界编辑区显示；普通正文、多行及转义正文保留缩进，粘贴和管道不触发补全。不查询或猜测标识，不自动执行；Enter 后继续使用原认证、SDK、取消与来源检查。没有新增服务协议或凭据流程。

下一步可按实际需求增加输入历史选择，也可推进记忆检索体验。输入历史需先明确是否仅保存在当前进程及敏感输入处理规则；检索迭代先明确相关性、无结果提示及来源撤回规则，再决定实现。不要顺带接回旧群聊记忆。来源管理面板仍使用显式重新加载，不自动合并其他设备的选择，新会话不会自动获权。

记忆提取和检索优化需先定义来源撤回、保留及历史事实更新规则。共享会话需先设计成员授权及资料可见性；不要通过字符串 ID 推断权限。桌面、iOS、Android 继续暂停。
