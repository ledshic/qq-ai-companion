# CLI 进程内输入历史记录

2026-10-29，面向使用者和仓库维护者。交互式 CLI 已支持选择、编辑和再次使用本次进程中的输入记录。记录仅保存在当前终端编辑器内存中，不写入文件，不从文件或服务端加载。退出 CLI 后不保留记录，新的编辑器实例从空记录开始。

## 选择与编辑

使用原有凭据进入 `pnpm agent:cli chat`。认证完成后，终端编辑器开始保留由 Enter 本地受理的输入，支持多行内容和命令。

| 按键或命令 | 行为 |
| --- | --- |
| Ctrl+P | 从最近一条开始选择，再向较早的记录移动 |
| Ctrl+N | 选择较新的记录；越过最新项返回原草稿 |
| Ctrl+O | 结束本次浏览，恢复开始选择前的草稿和光标位置 |
| Enter | 明确执行或发送选中的输入，仍经过原有检查 |
| Ctrl+G | 清空当前编辑区并结束浏览 |
| `/clear-input-history` | 清除本次输入记录和浏览快照，保留当前编辑区 |

方向键仍移动多行输入光标，Tab 仍执行命令补全或正文缩进。取回历史不会发送请求或自动执行；在同一次浏览中，各项的临时编辑与光标位置会保留，原记录不会被直接改写。

成功受理选中项后，原来的未发送草稿也会恢复，便于继续编辑。忙碌、提交未确认等本地检查拒绝输入时，选中项留在编辑区，不增加记录；可以 Ctrl+O 返回原草稿，再按原流程取消或显式重试。

历史只保存输入文字，执行时仍使用当前会话、当前任务列表和服务最新状态。例如 `/resume #1` 仍解释为当前列表的 #1，完整任务标识入口继续可用。新输入不会因为取回历史而绕过认证、取消或来源授权。

## 保留与敏感输入规则

- 最多保留 50 条，原文累计长度最多 64000，沿用 CLI 输入上限的字符串长度计数；超限时移除最早记录，每条仍最多 8000。
- 相邻且完全相同的记录合并；空输入不保留。输入以空格或其他空白字符开头时，跳过本次记录。
- 前导空白只影响本地记录，Enter 仍照常处理命令或发送消息。需要删除已有记录时使用 `/clear-input-history`。
- 记录表示编辑器接受了 Enter 输入，服务可能随后返回失败或结果未确认。历史选择不能生成另一个未确认提交，仍需 `/retry` 使用原标识确认。
- 不收集模型回答、流式草稿、服务端 `/history` 消息、启动凭据或 Ctrl+X 等直接快捷操作。用户明确输入的文字按上述规则记录，不尝试猜测其中的敏感内容。

清空时释放记录和浏览副本，退出时同时清除编辑器持有的历史、草稿与候选。当前输入由 Ctrl+G 清空，已提交消息继续按原有服务持久化规则保存，`/history` 继续读取当前会话的服务端消息。

## 显示与模式边界

选择时在编辑区显示“输入历史 序号/条数”，保留草稿、光标和补全提示。历史提示与流式草稿共同使用有界刷新区域，缩放或服务通知不会把选择变成提交。

非终端、管道和单次 CLI 不启用输入历史，也不解释历史选择快捷键。`/clear-input-history` 在非终端的普通命令模式中只返回没有保留历史的提示；多行正文仍按原规则作为文字处理。多行、粘贴、补全和退出规则沿用[编辑记录](AGENT-CLI-EDITOR.md)与[补全记录](AGENT-CLI-COMPLETION.md)。

实现使用编辑器实例内的有界容器，没有文件访问、全局输入缓存、新凭据或服务接口。浏览期间的编辑副本只随本次选择暂存；返回原草稿、清空或结束后释放。新的编辑器实例不继承其他实例的输入。
