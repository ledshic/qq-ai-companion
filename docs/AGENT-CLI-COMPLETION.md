# CLI 命令补全记录

2026-10-29，面向使用者和仓库维护者。交互式 CLI 已支持用 Tab 补全命令、任务状态和筛选参数。候选来自本地命令表、共享状态目录和现有参数解析，不查询会话、任务、凭据或文件；补全后仍需 Enter 执行。

## 使用方式

使用原有凭据进入 `pnpm agent:cli chat`，在可交互终端的单行命令中按 Tab。

| 输入示例 | Tab 的行为 |
| --- | --- |
| `/ta` | 补为 `/tasks ` |
| `/r` | 补足共同前缀 `/re`，显示 `/retry` 与 `/resume`；继续输入缩小范围 |
| `/tasks run` | 补为 `/tasks running ` |
| `/tasks c` | 显示 completed、cancelled，不自动选择 |
| `/tasks failed --h` | 补为 `--here ` |
| `/tasks running --conv` | 补为 `--conversation `，会话标识仍需明确输入 |

可补全命令包括 /help、/list、/tasks、/new、/use、/history、/clear-input-history、/retry、/resume、/cancel、/exit。任务状态覆盖 active、all 和六种具体状态，来源与正式 API（服务接口）相同。`/tasks more` 也可补全，但执行时仍检查是否存在可继续读取的列表。

唯一候选会替换光标所在的词，并在需要时补一个空格；同一行右侧参数保留。多个候选显示在编辑区，仅在光标位于词尾时补足共同前缀，不覆盖词中光标右侧的内容。方向键继续移动输入光标，不用于选择候选；重复 Tab 不轮流选择或自动提交。

## 参数与正文边界

筛选参数只提示交互式支持的 `--here`、`--conversation`。候选通过原有参数解析检查，排除重复参数、互斥会话条件、状态位置错误和 more 后的附加条件；也会考虑光标右侧已有参数。单次命令专用的 `--before`、`--limit` 不在交互式候选中。

等待会话标识等参数值时不猜测标识，也不补全文件、凭据、会话标题或任务编号。没有候选的命令位置保持原样。候选只表示语法可补全，不保证任务状态或执行权限满足；按 Enter 后仍由原有 CLI、SDK（共享服务客户端）和服务验证。

普通文本、多行正文及 `//` 转义正文中的 Tab 仍插入两个空格。括号粘贴中的 Tab 作为文本缩进处理，不触发补全；非终端或管道输入完全不启用补全，保留原有文本和命令规则。补全不会将正文里的命令文字拆成操作。

## 显示与任务流程

候选显示在输入附近，最多占三行，并受当前终端高度限制；过长时提示继续输入缩小范围。候选与草稿、输入共用有界刷新区域，不把每次 Tab 写成滚动记录。继续输入、移动、删除或执行命令会清除提示；流式草稿更新与服务通知保留正在编辑的内容和光标。

不增加认证入口或服务调用。认证仍在进入编辑器前完成；补全本身不读取凭据、不发送请求。取消、显式重试、任务恢复和来源授权检查仍使用原有服务与 SDK；Tab 不会自动取消、恢复、授予来源或重新提交任务。

输入上限仍为 8000 字符。补全若超限则整次拒绝，保留原输入；退出时清除本地候选和草稿，恢复原有终端输入及粘贴模式。完整按键和退出规则见[多行编辑记录](AGENT-CLI-EDITOR.md)。
